# Database

PostgreSQL via `database/sql` + `lib/pq`. Queries are generated by **sqlc**; schema changes are managed by **golang-migrate**.

## Migrations

- Location: `internal/infrastructure/database/pg/migrations/`
- Naming: `000NNN_snake_case.up.sql` and a matching `.down.sql` — always both.
- Files are **embedded in the binary** (`go:embed`) and applied automatically on startup by `pg.RunMigrations`. No files need to be copied into the runtime image.
- Never edit an applied migration; add a new one.

Conventions: UUID primary keys (`gen_random_uuid()`), `created_at` / `updated_at` `TIMESTAMPTZ`, inline `REFERENCES` with an explicit `ON DELETE`, indexes named `idx_<table>_<column>`. For larger services, give each module its own PostgreSQL schema (e.g. `orders.orders`).

## sqlc

- Config: `sqlc.yaml`. Queries: `internal/infrastructure/database/pg/queries/<module>.sql`.
- Annotate each query: `-- name: GetUserByID :one` (`:one`, `:many`, `:exec`). Inserts use `INSERT ... RETURNING` with `:one` (see `CreateUser`).
- Generate with `make sqlc`. The output (`pg/sqlc/`) is **gitignored**; `make run`, `make build`, `make test`, `make vet` and the Dockerfile regenerate it.
- Repositories wrap `*sqlc.Queries` and map rows to domain entities.

## Adding a table and query

1. Create `000002_create_orders_table.up.sql` / `.down.sql`.
2. Add queries to `queries/order.sql`, run `make sqlc`.
3. Implement `internal/infrastructure/repository/order.go` against the domain `Repository` interface.
4. Wire it in `application.New`.

## Transactions

`database.WithTransaction(ctx, tx)` stores a `*sql.Tx` in the context and `database.TransactionFromContext(ctx)` reads it, so a use case can open a transaction and let repositories join it:

```go
q := sqlc.New(db)
if tx, ok := database.TransactionFromContext(ctx); ok {
    q = q.WithTx(tx)
}
```

## Connection pool

Configured in `pg/connect.go`: `MaxOpenConns 25`, `MaxIdleConns 5`, `ConnMaxLifetime 5m`.
